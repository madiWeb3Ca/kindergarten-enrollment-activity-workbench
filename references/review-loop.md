# 第⑦⑧步 · 回头看效果与存下下次再用

> 第⑦步复盘验证：有没有用、断在哪一环、反馈什么、哪里改。第⑧步迭代回流：结论回灌成下一轮资产，形成自循环。

## 一、复盘时机

- **正式复盘攒到链路第二场**（园内探园/体验课）之后，两场数据合并看；单场不急于下结论。
- **当天先记原始记录**：到场、留资/加微/预约数、家长原话反馈、现场异常卡点，防记忆衰减；正式复盘在第二场后汇总。

## 二、复盘三问

| 问题 | 看什么 |
|---|---|
| 断在哪一环 | 对照漏斗：到场→留资→加微→预约→到园，哪一环流失最多 |
| 家长反馈什么 | 关注点、顾虑、意见；按主题标签归类，不记流水账 |
| 哪里要改 | 环节/时段/物料/伴手礼/话术，哪些保留、哪些调整 |

复盘结论要落到"下次改哪一句、换哪个材料/环节"，不写"本次活动效果良好"这类总结话。

## 三、回流去向

| 回流去向 | AI 加持版（本 skill 定位） | 人工常规版对照 |
|---|---|---|
| 社区资源库 | 存居委会/物业联系人、场地条件、通知渠道、合作方式、本场效果 | 同左（人工常规场景主要记这一项） |
| 活动原型字典 | 本场验证有效的变形组合沉淀为可复用配方，下场调用时再按新场地变形 | 不单独沉淀，只写本场简单总结 |
| 线索分层规则 | 沿用现有状态机归置活动线索；复盘发现缺场次/片区字段时，只在新表模板提建议，不动旧表 | 沿用现有状态机，不单独立回流动作 |
| 下一轮输入 | 复盘结论反哺下一场第①步定入口、第②步盘家底，形成自循环 | — |

## 四、两张新增表的归属

| 表 | 粒度 | 装什么 |
|---|---|---|
| 活动档案表 | 一场一行 | 本场方案要点、漏斗指标、复盘结论、回流条目、关联资源场所；HTML 方案卡作为美观视图挂该行或单独导出 |
| 外联资源库表 | 一场所一行 | 合作方基础信息、接洽状态、场地条件、合作方式、历史效果、关联场次编码 |

字段骨架见 `tables/activity-archive.md`、`tables/outreach-resource.md`。

### 录入与回流规则

1. **自动建表、人工确认**：两张底座表由工具按三级路径初始化（在线多维表格 → 本地 Excel → MD 文本，见下）；建表、配字段、调关联不派给使用者手工完成。每场活动/每个场所的回填条目由 AI 出初稿，人核对时间、地点、联系人、费用、师资、名额后落库。
2. **母版回流**：成品方案、有效打法、复盘结论回交母版；个人库是工作区，母版是汇总正本；第一阶段先各自就地录，跑一段时间后人工汇总去重分级。
3. **读取跟随**：参考历史活动或合作资源，去对方库或母版读；既有招生工作台与意向台账原样不动，需要时只读这两张新表。
4. **编码关联**：档案、资源条目、线索段挂场次编码/场所编码；不靠复制粘贴保持一致。
5. **隐私边界**：家长线索与联系方式留招生岗受控库，不进品宣共享表；资源库只记合作方信息。

### 工具口径

- **三级建表降级**：① 首选豆包内置打通的在线多维表格，由 AI 按 `tables/` 骨架直接新建；② 环境不支持在线表时，用 `scripts/init_tables.py --format xlsx` 生成本地 Excel 工作簿；③ Excel 也生成不了时，`--format md` 出 Markdown 表结构文本。不要求园方单独安装飞书；在线表归品宣项目空间，招生岗经链接只读；不单独做组织权限开通核验。
- 历史档案复用时，打法结构可参考；当时事实数字须重新核实，不直接沿用旧数据。

## 五、资源分级规则

| 级别 | 判断标准 | 动作 |
|---|---|---|
| P0 | 已合作或关系熟；在读家庭集中 | 优先排期，深化合作 |
| P1 | 距离近/家庭密度高；待接洽 | 列入近期接洽清单 |
| P2 | 条件一般或竞对密集；暂缓 | 暂不投入，定期回看 |

## 六、自循环闭环

```
第①步定入口 → 第②步盘家底 → 第③步选原型 → 第④步搭方案
→ 第⑤步校验 → 第⑥步留痕 → 第⑦步复盘 → 第⑧步回流
        ↑______________________________________________|
```

复盘结论回流后，下一场从第①②步重新校准：入口有没有变、家底有没有新增、原型配方要不要调整。
